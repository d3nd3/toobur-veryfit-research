TOOBUR / IDO — Heart rate → CSV

Requirements: Chrome (or Chromium) with Web Bluetooth. Serve this folder over HTTP — e.g. cd htmlapp && python3 -m http.server 8000 — then open http://localhost:8000/toobur-hr-csv.html. Do not use file://.

  • Many watches return no stored HR samples until you wear the band with HR logging on—use Heart rate mode & interval below (v3 or legacy) or VeryFit / confirmed-only.html.
  • HR CSV follows the JNI callback 7003 layout (sub_16DE1C): year, month, day, startTime, dataType, silentHR, five hrInterval slots (threshold u8 + minute u16 each), then items as minute-offset u8 + BPM u8 when the data length matches 2 × itemCount. Fallback heuristics if the header does not match.
Heart rate mode & measurement interval

v3 cmd 0x09 / evt 5010 (**IDOSetV3HeartRateModeBluetoothModel**): this page now uses one unified TX shape:

  • Unified TX 0x09: UPDATE_TIMESTAMP(4) + ON_OFF(2) + START-END(4) + INTERVAL(2 LE) + CRC. Two checkboxes can force timestamp/start-end bytes to all zero.

The matching RX replies always contain NULL_COMMAND + ON_OFF (state byte: CC = ON, AA = OFF, 99 = legacy ON, …) + INTERVAL (echoed, usually 300 s) + UNKNOWN + MODE?/reply (04 00 00 00) + CRC. `toobur-hr-csv.html` logs this block as state, interval and reply_code.

This page exposes one v3 HR mode path plus legacy 03 25. Canonical behaviour is a single unified 0x09 frame (Gadgetbridge and current tooling). The SDK model fields such as modeType and notification flags are reference only and are not fully mapped onto the bytes we transmit here.

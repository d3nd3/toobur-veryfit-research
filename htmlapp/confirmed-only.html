Angelfit sensor / motor (SET 0x50–0x53, VBUS 120–123)

Payloads match protocol.h: protocol_heart_rate_sensor_param (0x50), protocol_gsensor_param (0x51), protocol_set_real_time_health_data_status (0x52), protocol_set_start_motor (0x53). uint16_t fields are little-endian. Gadgetbridge ID115Constants also uses GET 0x02 0x20 / 0x02 0x21 and SET 0x03 0x24 / 0x03 0x25 (see below).

0x52 Realtime sensor (G-sensor + HR) — preset buttons

SET 03 52 = cmd + key + 2 payload bytes (protocol: gsensor status, HR sensor status). Below: four variants of ON/OFF byte pairs. Each variant sends the same value for both payload bytes (typical when mirroring ID115-style toggles). Use Isolate G to set only byte 0 (gsensor) with byte 1 fixed to 01 / 55.

Variant A — ON=0x01 / OFF=0x00 (numeric)
Variant B — ON=0xAA / OFF=0x55 (ID115-style AA/55)
Variant C — ON=0xCC / OFF=0x55
Variant D — ON=0x01 / OFF=0x55 (Gadgetbridge-style first byte; same as paired A/D)

Isolate G: byte 0 = gsensor trial value; byte 1 fixed to 01 (except full-pair OFF rows where both bytes use the OFF value). Tweak hex if your watch expects HR byte 55 when off.

0x30 Notice / call alert

Wire matches Angelfit protocol.h: struct protocol_set_notice after protocol_head (cmd=0x03, key=0x30) — fields in order notify_switch, notify_itme1, notify_itme2, call_switch, call_delay (five uint8_t). VeryFit pads to 20 bytes (15×00). OEM example: TX 03 30 88 00 00 AA 00 … (app_fresh_launch). ACK is struct protocol_set_notice_ack: same 03 30 head, then notify_switch (echo of what you set), status_code (often 0x01), err_code — e.g. 03 30 88 01 00 00 …. Values are often band tokens (0x55/0x88/0xAA) or small integers depending on stack; Flutter JSON “modes” are not the same as raw byte values.

V3 (cmd 0x33 — 33 DA AD DA AD…)

Extended protocol. Sub-command in bytes 4–5 (e.g. 0x0B 0x06 = watch face select). Ordered ascending by sub-cmd.

v3 0B 06 / 0B 07 — Watch face

v3 0C 0F — GET alarm (VBUS_EVT_FUNC_V3_GET_ALARM evt 5018)

Request alarm list from watch. Reply is multi-packet (353+2 CRC bytes); parsed alarms are loaded into the alarm list below. See logcat_dumps/get_alarm.txt.

v3 0x0E — Set sport type sort (setSportSortV3 / VBUS_EVT_FUNC_V3_SPORT_SORT)

Function table: getSportsTypeV3. Event: base_app_set + func_v3_sport_sort. JSON: num (1–30), item array of { index, type } — index from 1, type = sport type id. Same v3 cmd 0x0E as in set_alarms_and_sports.txt (evt 5017).

v3 health sizes (get_sync_health_v3.txt)

Get sizes = v3 cmd 0x05 (same as “Get health sizes” below). Then cmd 0x04 per type — TX bytes match ui_watch_face_write_json.txt / TOOBUR.md. Day data, save offset 0: types 0x01 SpO2, 0x02 pressure, 0x03 HR, 0x08 sport summary. Count data: 0x04 activity, 0x06 swim, 0x07 sleep (start sync; offset 00 00 00 in payload).

v3 health sync cmd 0x04 (start)

After seq: operate (byte 12), data_type (byte 13), byte 14 from template (often 0x01 on day types), then save offset 16-bit LE at bytes 15–16 (e.g. sport 01 4E 00 → offset 78 = 4E 00). Leave empty for logcat-style defaults: 1 for 0x01–0x03 / 0x08, 0 for 0x04 / 0x06 / 0x07.

v3 1A xx — Function table (raw)

Sends the captured 0x33 0x1A frame from app_fresh_launch.txt (cmd id 0x1A, seq 0x02) on devices where func table bit v3_function_table_33_1a is set. Reply will be tagged as a v3 function-table packet in the console.
